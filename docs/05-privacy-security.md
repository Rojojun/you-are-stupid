# 5. 개인정보·보안·운영 원칙

## 필수 원칙

1. **명시적 동의**: 도구·워크스페이스·동기화 계층별로 따로 선택한다. 설치 동의가 원문 클라우드 전송 동의가 되지 않는다.
2. **최소 수집**: 분석에 필요 없는 파일·키 입력·클립보드는 수집하지 않는다.
3. **원문 우선 로컬 보관**: 중앙 기본 모드는 가명 이벤트와 redacted summary다.
4. **목적 제한**: 개인 회고와 사용자가 요청한 리포트만 허용한다. 광고, 모델 학습, 고용/인사 평가는 별도 동의가 있어도 v1 범위 밖이다.
5. **사용자 통제**: 수집 범위 보기, 미리보기, 즉시 중지, 수정, 내보내기, 삭제를 제공한다.

## 민감 데이터 처리

- 동기화 전 탐지: API 키/비밀번호/토큰, 개인식별·결제 정보, 사설 키, `.env` 값, 일반적인 비밀 패턴.
- 처리: 기본은 자리표시자(`<REDACTED:API_KEY>`)로 치환한다. 탐지 불확실성은 업로드 전 사용자 검토 대기열로 보낸다.
- 욕설/감정 표현은 분석 목적상 민감한 대화 문맥이 될 수 있다. 원문은 로컬에 두고 중앙에는 최소한의 분류 결과와 비인용 근거만 전송한다.
- 소스 코드와 업무 문서가 섞일 수 있으므로 조직/프로젝트 단위의 제외 목록과 세션별 동기화 중지를 지원한다.

## 보안 설계 기준

| 영역 | 기준 |
| --- | --- |
| 로컬 vault | OS 보안 저장소로 보호한 키 + 검증된 암호화 라이브러리의 authenticated encryption |
| 전송 | TLS, 기기 등록 토큰의 회전과 폐기 |
| 중앙 저장 | 테넌트 분리, 저장 암호화, 최소 권한 서비스 계정 |
| 접근 | 사용자/관리자 권한 분리, 원문 접근은 별도 승인·감사 로그 |
| 감사 | 데이터 조회·export·삭제·동의 변경을 변조 방지 감사 로그에 기록 |
| 공급망 | 서명된 설치물, 자동 업데이트 검증, 의존성 취약점 점검 |

암호 알고리즘과 키 수명은 구현 시 보안 검토에서 확정한다. 제품 팀이 자체 암호를 설계하거나, 로그에 복호화 키·원문을 기록해서는 안 된다.

## 보존·삭제 초안

- 로컬 원문: 사용자가 삭제할 때까지 보관하되, 앱에서 기간별 자동 삭제를 선택할 수 있다.
- 중앙 이벤트·요약·분석: 기본 12개월. 실제 기간은 법률 검토와 사용자 선택 후 확정한다.
- 원문 동기화 모드: 기본 비활성, 별도 보존 기간·다운로드·즉시 삭제 안내가 필요하다.
- 삭제 요청: 중앙 원본, 검색 인덱스, 분석 결과, 백업 만료 일정을 구분해 상태를 보여 준다. 이미 집계된 완전 비식별 통계의 처리 원칙도 약관/설정에 명시한다.
