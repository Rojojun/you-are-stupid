# 6. 9월 22일 설계 완료 기준과 이후 실행 순서

## 9월 22일 완료물

이번 마감은 제품 구현 완료가 아니라 **구현을 안전하게 시작할 수 있는 설계 패키지 완료**로 정의한다.

- [x] 제품 범위, 비목표, 사용자 흐름
- [x] macOS/Windows 로컬 수집기와 중앙 분석 서비스의 책임 경계
- [x] 원문·축약문·이벤트·분석 결과의 분리 저장 계약
- [x] 중앙 활동 taxonomy와 욕설/마찰·질문 성장 평가 기준
- [x] 동의·보안·보존·삭제·법무 검토 게이트
- [x] API 초안과 커넥터 capability 계약
- [ ] 도구별 실제 커넥터 가능성 검증표 — 제품 버전/계정/권한을 확인해야 확정 가능
- [ ] 법무·보안 승인 — 외부 전문 검토가 필요

마지막 두 항목은 문서만으로 완료되었다고 주장할 수 없다. 둘 다 통과하기 전에는 실제 자동 수집이나 원문 중앙 동기화를 배포하지 않는다.

## 구현 순서

| 단계 | 산출물 | 완료 판정 |
| --- | --- | --- |
| 0. 결정 고정 | 데이터 흐름도, 동의 화면 문구, 보존 기간 | 제품·법무·보안 책임자가 승인 |
| 1. 로컬 기반 | vault, 수동 import, 원문/요약 분리, 삭제 | macOS/Windows에서 offline 테스트 통과 |
| 2. 중앙 최소판 | ingestion, event store, taxonomy v1, 리포트 | 멱등/권한/삭제 계약 테스트 통과 |
| 3. 분석 품질 | 평가 세트, 정정 UI, 신뢰도 표시 | 사람 검토와의 일치율·정정률 기준 통과 |
| 4. 커넥터 | 도구별 공식/읽기 전용/import connector | 각 도구의 허용 범위·회귀 테스트 통과 |
| 5. 제한 베타 | opt-in 사용자, 보안 모니터링 | 원문 유출 0, 삭제·중지·복구 시나리오 통과 |

## 단계 0에서 확정해야 할 결정

1. 개인용 제품만 할지, 조직 워크스페이스도 지원할지. 조직 지원은 관리자의 원문 열람 금지와 근로감시 법률 검토를 별도 요구한다.
2. 중앙에 보낼 기본값을 `이벤트+요약`으로 고정할지. 이 설계는 그것을 권장한다.
3. 원문 동기화가 필요한 실제 사용 사례와 보존 기간. 없으면 기능을 만들지 않는다.
4. “Antigravity”가 어떤 제품/배포판을 뜻하는지와 사용 계정 유형. 커넥터 호환성은 이 식별 없이는 확정할 수 없다.
5. 질문 성장 결과를 개인 대시보드에만 표시할지. 공유·랭킹 기능은 v1에서 제외한다.

## 첫 구현 스프린트의 세부 작업

1. 공통 이벤트 스키마를 JSON Schema/OpenAPI로 고정하고 fixture 20개를 만든다.
2. macOS/Windows 공통 데스크톱 런타임을 선정하고, OS 보안 저장소를 이용한 vault spike를 만든다.
3. 파일 import 전용 Codex fixture부터 원문·요약·이벤트 분리를 검증한다. 아직 자동 탐색은 하지 않는다.
4. 중앙 `POST /ingestions/batches`와 멱등성·redaction·삭제 계약 테스트를 만든다.
5. taxonomy v1의 사람 라벨 평가 세트를 만들고, 중앙 분류기 결과에 근거·신뢰도를 붙인다.
6. 사용자가 분류를 정정하고 원문을 삭제/내보내는 최소 화면을 만든다.

## 출시 차단 조건

- 사용자 동의 없이 프롬프트, 응답, 파일, 클립보드 또는 키 입력을 수집하는 경로
- 원문과 요약이 구분되지 않아 삭제 범위를 설명할 수 없는 상태
- 토큰을 추정하면서 실제 사용량으로 표시하는 리포트
- 욕설만으로 사용자 성격·감정을 확정하거나 불이익을 주는 분석
- 커넥터의 데이터 접근 근거와 변경 감지가 없는 배포
