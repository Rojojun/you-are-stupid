# 4. 중앙 분류와 성장 측정 기준

## 왜 중앙에서 판단하는가

“진행 상황 어때?”는 단독으로 보면 단순 진행 확인이다. 그러나 직전의 여러 작업 지시·도구 실패·대기 상태가 있으면 에이전트가 멈춘 뒤 생긴 재촉일 수 있다. 반대로 “틀린 결론을 고집하네”는 욕설이 없어도 교정 신호다. 이처럼 의미는 한 문장보다 대화 창(window)과 순서에 있으므로, 기기마다 다른 규칙으로 확정하지 않고 중앙에서 같은 taxonomy와 모델 버전으로 판정한다.

로컬은 후보 태그와 안전하게 축약된 전후 문맥을 보낼 수 있지만 최종 분류를 확정하지 않는다. 중앙 결과도 절대적 진실이 아니며, 사용자의 정정이 우선이다.

## 활동 taxonomy v1

| 분류 | 정의 | 예시 신호 | 제외 기준 |
| --- | --- | --- | --- |
| `productive_work` | 새 작업 지시, 질문, 의사결정 | 요구사항, 코드/문서 요청, 선택 | 이전 작업을 단순 반복하는 재지시 |
| `agent_correction` | 잘못된 방향·범위·모델 변경을 바로잡음 | “묻지 않고 바꿨다”, 오류 근거 제시 | 정상적인 추가 요구사항 |
| `progress_check` | 현재 상태·차단 사유를 확인 | “진행 상황 어때?” | 멈춤 뒤 재개 지시가 핵심인 경우 |
| `cross_agent_handoff` | 한 도구/채팅의 맥락을 다른 곳에 전달 | 복사한 요약, 전달 요청 | 원문 단순 백업 |
| `resume_instruction` | 기다리는 에이전트를 재개 | “계속”, “진행해”, “응” | 새 작업의 구체 지시 |
| `simplify_explanation` | 설명 수준을 낮추거나 재표현 요청 | “쉬운 말로” | 새 정보 요청 |
| `rule_reminder` | 이전에 합의한 제약을 재고지 | 운영체제/범위/형식 재확인 | 처음 제시한 규칙 |
| `other` | 명령 조각, 인사, 분류 불가 | 슬래시 명령 | 위 분류로 충분히 설명되는 경우 |

한 발화에는 주분류 하나와 보조분류 여러 개를 둘 수 있다. 따라서 전체 비율은 **발화 수가 아니라 시간/토큰 가중 세션 구간** 기준으로 계산하고, 분모를 화면에 명시한다. 사용자가 제시한 55%, 13%, 9.5% 등은 제품 초기의 가설적 기준선이며 다른 사용자에게 목표값이나 평가 기준으로 적용하지 않는다.

## 마찰·욕설 분석

`profanity`는 별도 활동 분류가 아니라 `ReactionSignal`이다. 원문 용어 목록의 단순 매칭만으로 분노나 공격성을 확정하지 않는다.

```text
AI 응답/도구 결과
  → 사용자 오류 지적 또는 재지시
  → AI가 정정했는지 / 같은 오류를 반복했는지
  → 강한 부정·욕설·대문자·짧은 반복 응답
  → friction: low | medium | high, 원인 후보와 신뢰도
```

표시 예: “이 세션에서 높은 마찰 신호가 1회 있었습니다. 직전 3개 이벤트에는 범위 변경 지적과 재지시가 있었습니다.” “사용자가 화를 냈다”처럼 단정하거나, 욕설 원문을 대시보드에 기본 노출하지 않는다.

일간·주간·월간 집계에는 욕설 감지 횟수, 중간 이상 마찰 신호 횟수, 에이전트 교정 횟수,
질문 명확도 평균과 이전 기간 대비 변화량을 기록한다. 욕설 감지 횟수는 감정의 강도나
사용자 평가가 아니라 대화 마찰을 점검하기 위한 관측값이다.

## 질문 성장 측정

주·월별로 아래 다섯 축을 0–3 척도로 측정한다. 한 세션의 점수보다 충분한 표본이 쌓인 기간 중앙값과 변화 폭을 보여 주며, 도구·작업 종류에 따른 차이를 함께 표시한다.

| 축 | 0 | 3 |
| --- | --- | --- |
| 목표 명확성 | 요청 목표가 없음 | 완료 상태와 산출물이 분명함 |
| 맥락 제공 | 관련 배경 없음 | 현재 상태·참조·제약이 연결됨 |
| 제약 명시 | 범위·권한 불명 | 변경/검증/권한 경계가 명확함 |
| 검증 요청 | 결과 확인 없음 | 테스트·근거·불확실성을 요구함 |
| 의사결정 후속 | 끝맺음 없음 | 선택·승인·다음 행동이 명시됨 |

이 수치는 언어 능력, 직무 역량, 인성의 점수가 아니다. 짧은 “계속”은 역할상 적절할 수 있으므로 낮은 품질로 처리하지 않는다. 분류 모델은 익명화한 사용자 정정 샘플과 사전 정의된 평가 세트에서 버전별 정확도·불일치율을 검증한 뒤 배포한다.

## 분석 파이프라인

1. 시간 순서 보정과 역할/도구 이벤트 결합
2. 비밀값 제거 및 세션 요약 생성
3. 규칙 기반 후보 추출(예: 재개 표현, 진행 확인 표현)
4. 중앙 문맥 분류 모델의 주·보조 분류, 마찰 원인, 신뢰도 산출
5. 낮은 신뢰도 또는 민감한 욕설 신호는 보수적으로 표시
6. 사용자 정정 저장 → 주기적 오프라인 평가 → 새 모델 버전 검증
